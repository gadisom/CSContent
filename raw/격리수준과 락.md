 락(lock): 다른 트랜젝션이 못 건드리게 잠금 
격리수준: 트랜젝션끼리 서로 얼마나 간섭 허용할지 규칙 

왜 필요 ? 
여러 요청이 동시에 db에 접근할 때 
A: 잔액 100 -> 0으로 출금 
B: 동시에 조회 -> 100 으로 읽음 
동시성으로 인한 잘못된 데이터 발생
그래서 락으로 막거나 격리 수준으로 정책 정함 

### Lock 
-> 내가 쓰는 동안 너 건드리지마 
종류 
1. Shared Lock (읽기 락): 읽기만 가능, 쓰기 X -> Select 할때 사용 

2. Exclusive Lock (쓰기 락):  읽기 x , 쓰기 x -> update, delete 할때 
		A: UPDATE 실행 → Exclusive Lock 획득
		B: SELECT 시도 → 대기
		B는 A 끝날때 까지 기다림 

### 격리 수준 (Isolation Level)
![[Pasted image 20260503224010.png]]
트랜잭션 간 간섭을 어디까지 허용할거냐 
1. Read Uncommitted(최하)
		커밋 안된 데이터도 읽음 
		문제: Dirty Read 발생 
		A: 값 100 -> 0 (아직 커밋 안함) 
		B: 0 읽음 
		A: rollback -> 다시 100 
		B는 존재하지 않는 값을 읽음 

2. Read Committed (많이 씀)
	커밋 된것만 읽음 
	but 
	Non-repetable read 발생 
	A: 값 100 읽음
	B: 200으로 변경 후 commit
	A: 다시 읽음 → 200
	같은 쿼리가 결과가 바뀜 

3. Repeatable Read - 한 트랜젝션 내에서 같은 값 유지 
	하지만 Phantom Read 발생 
	A: WHERE age > 20 → 10명
	B: 새로운 데이터 추가
	A: 다시 조회 → 11명
	-> 유령 데이터
