> TCP와 UDP는 전송 계층에서 애플리케이션 간 데이터 전달 방식을 결정하는 프로토콜로, TCP는 신뢰성을, UDP는 단순성과 낮은 지연을 우선한다.

## 정의
- TCP: 연결 지향 프로토콜이다. 데이터를 보내기 전에 연결을 맺고, 데이터 순서 보장, 손실 시 재전송, 흐름 제어, 혼잡 제어를 통해 신뢰성 있는 전송을 제공한다.
- UDP: 비연결 지향 프로토콜이다. 연결 설정 없이 데이터를 바로 보내며, 헤더가 단순하고 처리 비용이 낮다. 대신 순서 보장, 재전송, 중복 제거 같은 기능은 기본으로 제공하지 않는다.
- 전송 계층: TCPIP 모델에서 애플리케이션 사이의 데이터 전달 방식을 담당하는 계층이다. IP가 목적지 호스트까지의 전달을 다룬다면, TCP와 UDP는 어떤 애플리케이션으로 어떤 방식으로 전달할지를 다룬다.
- 포트 번호: 같은 IP 주소를 가진 호스트 안에서 특정 애플리케이션이나 서비스를 구분하는 번호다. 예를 들어 웹 서버는 보통 HTTP 80번, HTTPS 443번 포트를 사용한다.
- 신뢰성: TCP에서 말하는 신뢰성은 데이터가 반드시 빠르다는 뜻이 아니라, 손실된 데이터를 다시 보내고 순서를 맞춰 애플리케이션이 올바른 데이터 흐름을 받게 한다는 뜻이다.
- TCP와 UDP의 차이는 신뢰성, 지연, 오버헤드, 애플리케이션 보완 가능성을 기준으로 비교하면 선명해진다.

## 핵심 포인트
- TCP는 연결 수립 과정이 필요하다. 대표적으로 3-way handshake를 통해 클라이언트와 서버가 서로 통신 가능한 상태인지 확인한 뒤 데이터를 주고받는다.
- TCP는 데이터를 세그먼트로 나누어 보내고, 수신 측의 ACK를 바탕으로 도착 여부를 확인한다. 일부 데이터가 손실되면 재전송하고, 순서가 바뀌어 도착하면 다시 정렬해 애플리케이션에 전달한다.
- TCP의 흐름 제어는 수신자가 처리할 수 있는 양을 넘지 않도록 송신 속도를 조절하는 기능이다. 혼잡 제어는 네트워크 자체가 과부하되지 않도록 전송량을 조절하는 기능이다.
- UDP는 연결 수립, ACK 기반 재전송, 순서 보장 같은 기능을 생략한다. 그래서 오버헤드가 낮고 지연이 작지만, 패킷 손실이나 순서 뒤바뀜을 애플리케이션이 감수하거나 직접 보완해야 한다.
- TCP는 파일 다운로드, 로그인, 결제, 일반적인 웹 요청처럼 데이터 정확성이 중요한 상황에 어울린다. 일부 지연이 있더라도 데이터가 온전하게 도착하는 것이 더 중요하기 때문이다.
- UDP는 실시간 게임, 음성 통화, 영상 스트리밍, DNS 질의처럼 낮은 지연이나 빠른 질의응답이 중요한 상황에서 자주 쓰인다. 일부 데이터 손실보다 늦게 도착하는 데이터가 더 문제가 될 수 있다.
- UDP가 항상 TCP보다 빠르다고 단정할 수는 없다. 네트워크 상태, 애플리케이션 구현, 재전송을 애플리케이션에서 직접 처리하는지에 따라 실제 성능은 달라진다.
- 최근 프로토콜인 QUIC은 UDP 위에서 동작하면서 연결 관리, 암호화, 재전송 같은 기능을 애플리케이션 계층에 가깝게 구현한다. 이는 UDP가 단순한 기반을 제공하고, 필요한 신뢰성은 위 계층에서 설계할 수 있다는 예시다.
- 프로토콜 선택의 핵심은 “무엇이 더 좋은가”가 아니라 “이 서비스에서 정확성, 순서, 지연, 구현 복잡도 중 무엇을 우선할 것인가”이다.

- UDP는 기본적으로 ACK 기반의 신뢰성 보장을 제공할까?
