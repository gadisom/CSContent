> [DNS는 사람이 읽기 쉬운 도메인 이름을 실제 서버를 찾기 위한 IP 주소로 바꿔주는 분산 이름 해석 시스템이다.]{.lead}

## 정의
![[dns-resolution-flow.png]]

- [DNS]{.term}는 도메인 이름을 IP 주소와 같은 네트워크 주소 정보로 변환하는 시스템이다.
- 사용자가 도메인을 입력하면 브라우저, 운영체제, [로컬 DNS 캐시]{.term}를 먼저 확인하고 없으면 [재귀 해석기]{.term}에게 질의한다.
- 재귀 해석기는 필요한 경우 [루트 네임서버]{.term}, [TLD 네임서버]{.term}, [권한 있는 네임서버]{.term}를 차례로 조회해 최종 레코드를 얻는다.
- 권한 있는 네임서버는 특정 도메인에 대한 실제 [DNS 레코드]{.term}를 관리하는 서버다.
- DNS 응답은 [TTL]{.term} 동안 캐시될 수 있으며, 캐시는 반복 조회 시간을 줄이고 전체 DNS 트래픽을 낮춘다.
- [A 레코드]{.term}는 도메인을 IPv4 주소에, [AAAA 레코드]{.term}는 IPv6 주소에 연결한다.
- [CNAME]{.term}은 별칭을 다른 도메인 이름으로 연결하고, [MX]{.term}는 메일 서버 정보를 나타낸다.

## 핵심 포인트
- [DNS는 웹 요청 흐름에서 서버 주소를 찾는 초기 단계]{.accent}다.
- 캐시가 있으면 루트부터 권한 있는 네임서버까지 매번 조회하지 않아도 된다.
- [재귀 질의]{.term}는 클라이언트 대신 DNS 해석기가 최종 답을 찾아주는 방식이다.
- [반복 질의]{.term}는 다음에 물어볼 서버 정보를 단계적으로 받으며 찾아가는 방식이다.
- [TTL이 너무 길면 변경 반영이 늦고, 너무 짧으면 조회 부하가 늘 수 있다.]{.warning}
- [DNS가 실패하면 서버가 정상이어도 사용자는 도메인으로 서비스에 접근하지 못할 수 있다.]{.danger}

- A, AAAA, CNAME 레코드의 차이는 무엇인가요?

## 확인 문제
- DNS는 도메인을 IP로 바꾸는 역할을 할까?
- 캐시가 있으면 조회 단계를 줄일 수 있을까?
- 권한 있는 네임서버는 특정 도메인의 DNS 레코드를 관리할까?
- TTL이 지나면 캐시된 DNS 응답은 다시 확인이 필요할까?
- A 레코드는 IPv4 주소와 관련이 있을까?
