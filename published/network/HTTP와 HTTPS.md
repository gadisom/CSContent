> [HTTP는 평문 기반 애플리케이션 프로토콜이고, HTTPS는 TLS를 더해 기밀성과 무결성, 인증을 강화한 형태다.]{.lead}

## 정의
![[http-vs-https-flow.png]]

- [HTTP]{.term}는 웹에서 클라이언트와 서버가 요청과 응답을 주고받기 위한 애플리케이션 계층 프로토콜이다.
- HTTP 메시지는 기본적으로 [평문]{.term}으로 오가므로 중간에서 내용을 엿보거나 변조할 위험이 있다.
- [HTTPS]{.term}는 HTTP 통신을 [TLS]{.term}로 감싸 보호하는 방식이다.
- TLS는 [인증서]{.term}로 서버 신원을 확인하고, [비대칭키 기반 키 교환]{.term}으로 클라이언트와 서버가 함께 사용할 대칭키를 만든다.
- 실제 HTTP 데이터는 핸드셰이크 이후 만들어진 [세션 키]{.term}로 대칭키 암호화되어 오간다.
- 이 과정으로 HTTPS는 [기밀성, 무결성, 서버 인증]{.accent}을 제공한다.
- HTTP는 기본 포트로 [80번]{.term}, HTTPS는 기본 포트로 [443번]{.term}을 사용한다.
- HTTPS는 별도의 완전히 다른 요청 형식이 아니라, [HTTP 요청과 응답을 안전한 채널 위에서 주고받는 형태]{.accent}다.

## 핵심 포인트
- [HTTPS는 HTTP에 TLS 보안 계층을 더한 형태]{.accent}다.
- 핵심 보안 가치는 [기밀성]{.term}, [무결성]{.term}, [인증]{.term}이다.
- 암호화는 내용을 숨기고, 무결성 검사는 변조를 감지하며, 인증서는 서버 신원을 확인한다.
- [비대칭키는 상대 인증과 안전한 키 교환]{.term}에 쓰이고, [대칭키는 실제 데이터 암호화]{.term}에 쓰인다.
- 대칭키를 쓰는 이유는 비대칭키보다 빠르기 때문에 많은 HTTP 데이터를 처리하기에 적합하기 때문이다.
- [HTTPS를 사용해도 서버 코드 취약점이나 잘못된 인증 처리가 자동으로 해결되지는 않는다.]{.warning}
- 현대 웹에서는 로그인, 결제, 개인정보 전송뿐 아니라 일반 페이지도 HTTPS 사용이 기본에 가깝다.
- 브라우저는 HTTPS 여부를 보안 표시, 쿠키 정책, 권한 API 동작 등에 반영한다.
