> TCPIP 모델은 실제 인터넷 통신을 설명하는 계층 모델로, 애플리케이션 데이터가 여러 프로토콜을 거쳐 네트워크로 전달되는 흐름을 이해하게 해준다.

## 정의
- TCPIP 모델: 인터넷에서 실제로 널리 쓰이는 프로토콜 묶음을 계층으로 나누어 설명하는 모델이다. 보통 네트워크 접근 계층, 인터넷 계층, 전송 계층, 응용 계층의 4계층으로 이해한다.
- 네트워크 접근 계층: 같은 네트워크 안에서 실제 매체를 통해 데이터를 전달하는 계층이다. 이더넷, Wi-Fi, MAC 주소, 프레임 같은 개념이 이 계층과 관련 있다.
- 인터넷 계층: 서로 다른 네트워크 사이에서 목적지까지 데이터를 보내기 위한 주소 지정과 라우팅을 담당한다. IP가 대표적이며, 데이터는 패킷 단위로 다뤄진다.
- 전송 계층: 송신 애플리케이션과 수신 애플리케이션 사이의 전달 방식을 담당한다. TCP는 신뢰성 있는 연결 기반 전송을 제공하고, UDP는 가볍고 빠른 비연결 전송을 제공한다.
- 응용 계층: 사용자가 접하는 서비스와 애플리케이션 프로토콜이 위치하는 계층이다. HTTP, DNS, SMTP, FTP 같은 프로토콜을 이 관점에서 볼 수 있다.
- OSI 7계층과의 차이: OSI는 역할을 7개로 나눈 참조 모델이고, TCPIP 모델은 실제 인터넷 프로토콜 구조에 더 가까운 실용 모델이다.

## 핵심 포인트
- TCPIP 모델은 실제 인터넷 구현을 이해하기 위한 모델이다. OSI 7계층보다 계층 수는 적지만, 웹 요청이나 서버 통신을 설명할 때 더 직접적으로 연결된다.
- 응용 계층의 HTTP 요청은 전송 계층의 TCP 또는 UDP를 사용하고, 인터넷 계층의 IP를 통해 목적지 네트워크로 이동하며, 네트워크 접근 계층을 통해 실제 링크로 전달된다.
- IP는 목적지까지 가는 주소와 경로를 다루지만, 데이터가 반드시 도착했는지 보장하지는 않는다. 신뢰성이 필요하면 TCP 같은 전송 계층 프로토콜이 보완한다.
- TCP와 UDP는 둘 다 전송 계층 프로토콜이지만 목표가 다르다. TCP는 순서 보장과 재전송을 통해 안정성을 높이고, UDP는 연결 설정 비용을 줄여 지연을 낮춘다.
- 포트 번호는 같은 호스트 안에서 어떤 애플리케이션으로 데이터를 전달할지 구분하는 데 사용된다. IP가 호스트를 찾는다면, 포트는 그 안의 프로세스나 서비스를 찾는 단서가 된다.
- 면접에서는 TCPIP 모델을 외운 계층 이름으로만 말하지 말고, “HTTP 데이터가 TCP, IP, 이더넷을 거쳐 캡슐화되어 전달된다”는 흐름으로 설명하면 좋다.
