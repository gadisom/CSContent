> 데이터베이스는 애플리케이션의 데이터를 오래, 정확하게, 함께 사용할 수 있도록 관리하는 핵심 저장 계층이다.

## 정의
- 데이터베이스: 데이터를 일정한 구조와 규칙에 따라 저장하고, 필요한 데이터를 빠르고 일관되게 조회·수정할 수 있게 만든 저장 체계다.
- DBMS: 데이터베이스를 직접 관리하는 소프트웨어다. 애플리케이션은 보통 DBMS에 요청을 보내 데이터를 읽고 쓰며, DBMS는 저장 방식과 동시 접근, 복구 같은 내부 처리를 맡는다.
- 파일 시스템과 데이터베이스의 차이: 파일 시스템은 데이터를 파일로 보관하는 범용 저장 방식이고, 데이터베이스는 조회, 변경, 관계, 규칙, 동시 접근을 데이터 관리 관점에서 다룬다.
- 데이터베이스가 필요한 이유: 서비스가 커질수록 단순 저장보다 검색, 중복 관리, 여러 사용자 접근, 장애 후 복구, 권한 관리 같은 요구가 중요해지기 때문이다.
- 관계형 데이터베이스: 데이터를 테이블, 행, 열로 표현하고 SQL로 조회하는 방식이다. 현재 많은 서비스에서 기본 저장소로 사용된다.
- 면접에서는 데이터베이스를 “데이터를 저장하는 곳”에서 멈추지 말고, 애플리케이션이 신뢰할 수 있는 데이터를 계속 사용하게 해주는 관리 계층으로 설명하는 편이 좋다.

## 핵심 포인트
- 데이터베이스의 핵심 목적은 데이터를 영구적으로 저장하고, 필요할 때 정확하게 조회하며, 여러 사용자가 함께 써도 신뢰할 수 있게 유지하는 것이다.
- DBMS는 저장소와 애플리케이션 사이에서 데이터 접근을 표준화한다. 그래서 애플리케이션은 파일 위치나 저장 구조보다 “어떤 데이터가 필요한가”에 집중할 수 있다.
- 데이터베이스를 이해할 때는 저장, 조회, 변경, 제약, 관계, 동시성, 복구라는 문제 영역을 큰 지도처럼 잡는 것이 중요하다.
- 세부 주제는 각각 독립적으로 이어진다. 조회 성능은 인덱스, 안전한 변경은 트랜잭션, 동시 접근은 격리 수준과 락, 구조 설계는 정규화와 키 설계에서 더 깊게 다룬다.
- 좋은 데이터베이스 설명은 특정 기능 하나가 아니라 “데이터를 신뢰 가능한 상태로 유지하면서 서비스가 계속 읽고 쓰게 하는 시스템”이라는 관점에서 출발한다.

## 면접 질문
- 데이터베이스를 왜 사용하나요?
- 파일 시스템 대신 DBMS를 쓰는 이유는 무엇인가요?
- DBMS가 제공하는 주요 기능에는 어떤 것들이 있나요?
- 데이터베이스를 단순 저장소라고만 설명하면 부족한 이유는 무엇인가요?
- 관계형 데이터베이스는 데이터를 어떤 형태로 표현하나요?

## 확인 문제
- 데이터베이스의 역할은 저장만일까?
- 여러 사용자가 동시에 접근하면 제어가 필요할까?
- DBMS는 장애가 발생했을 때 복구 기능을 제공할까?
- 관계형 데이터베이스는 보통 테이블 형태로 데이터를 표현할까?
- 데이터베이스 기본을 이해한 뒤 인덱스, 트랜잭션, 정규화 같은 세부 주제로 확장할 수 있을까?
