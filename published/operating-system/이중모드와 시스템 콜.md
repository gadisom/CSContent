> [이중모드]{.lead}는 CPU 실행 권한을 [유저 모드]{.term}와 [커널 모드]{.term}로 분리해 시스템 자원을 보호하는 기법이며, 앱이 하드웨어에 접근하려면 반드시 [시스템 콜]{.term}이라는 공식 통로를 거쳐야 한다.

## 정의
- [이중모드(Dual Mode)]{.term}: 시스템 자원을 보호하기 위해 CPU 명령 실행 단계를 유저 모드와 커널 모드로 분리하는 보안 기법. 모드 비트(Mode Bit)로 현재 실행 권한을 구분한다

![이중모드](https://jnbrtpfewiftflohavzt.supabase.co/storage/v1/object/public/blog-images/1781268601666-iu98ywp6dj.png)

- [유저 모드(User Mode)]{.term}: 일반 응용 프로그램이 실행되는 모드. Mode Bit = 1. 자신에게 할당된 메모리에만 접근 가능하며, 커널 영역 접근 시도 시 CPU가 예외(Exception)를 발생시켜 프로세스를 강제 종료한다
- [커널 모드(Kernel Mode)]{.term}: 운영체제 커널이 실행되는 모드. Mode Bit = 0. CPU 명령어, 메모리 영역, 하드웨어, 인터럽트 등 모든 시스템 자원에 제한 없이 접근할 수 있다
- [시스템 콜(System Call)]{.term}: 유저 모드 프로그램이 커널 모드의 기능을 안전하게 사용하기 위해 OS에 요청하는 공식 인터페이스. 소프트웨어 인터럽트(트랩)를 발생시켜 모드를 전환한다
- [트랩(Trap)]{.term}: 시스템 콜 호출 시 발생하는 소프트웨어 인터럽트. ARM에서는 `svc`, x86에서는 `syscall` 명령어로 발생시키며 CPU 모드 비트를 0으로 변경한다
- [시스템 콜 테이블]{.term}: 시스템 콜 번호와 커널 내 처리 함수를 매핑한 테이블. 예를 들어 `open` 호출은 번호 5번으로 등록되어 `sys_open()` 함수가 실행된다

![시스템 콜 실행 과정](https://jnbrtpfewiftflohavzt.supabase.co/storage/v1/object/public/blog-images/1781270622819-7ec55unxctt.png)

## 핵심 포인트
- [모드 전환은 세 가지 경우에 발생]{.accent}한다. ① 시스템 콜(앱의 의도적 요청) ② 하드웨어 인터럽트(키보드, 타이머 등 외부 장치의 비동기 신호) ③ 예외(0으로 나누기, 잘못된 메모리 접근, 페이지 폴트 등)
- 앱이 `open()` 같은 파일 함수를 호출하면, 실제로는 [라이브러리 → 트랩 발생 → 커널 핸들러 실행 → 결과 반환 → 유저 모드 복귀]{.accent} 순서로 동작한다. 앱은 커널 내부 구현을 알 필요가 없다
- 유저 모드에서 장애가 나면 해당 프로세스만 종료되지만, [커널 모드에서 오류가 나면 전체 시스템이 다운]{.warning}될 수 있다. 이중모드의 핵심 가치가 여기에 있다
- 시스템 콜은 역할에 따라 [프로세스 제어]{.term}(생성·종료·대기), [파일 관리]{.term}(열기·읽기·쓰기·삭제), [메모리 관리]{.term}(할당·해제·매핑), [네트워크]{.term}(소켓·연결·전송), [장치 관리]{.term}로 분류된다
- 모든 프로세스는 별도의 가상 주소 공간을 갖지만, [커널 주소 공간은 모든 프로세스가 공유]{.accent}한다. 커널 모드 접근은 시스템 콜을 통해서만 허용된다
