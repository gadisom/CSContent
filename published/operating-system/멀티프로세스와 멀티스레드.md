> [멀티프로세스와 멀티스레드는 작업을 동시에 처리하기 위한 방식이지만, 격리와 공유를 어디까지 허용할지가 다르다.]{.lead}

## 정의
![[multi-process-vs-multithread.png]]

- [멀티프로세스]{.term}는 하나의 작업을 여러 프로세스로 나누거나, 여러 작업을 각각 독립 프로세스로 실행하는 방식이다.
- 각 프로세스는 독립적인 주소 공간을 가지므로 기본적으로 메모리를 직접 공유하지 않는다.
- [멀티스레드]{.term}는 하나의 프로세스 안에서 여러 스레드가 같은 주소 공간을 공유하며 실행되는 방식이다.
- 멀티프로세스는 프로세스 사이의 격리가 강하고, 멀티스레드는 공유 메모리를 통한 협업이 빠르다.
- 프로세스 사이 데이터 교환에는 [IPC]{.term}가 필요하고, 스레드 사이 공유 데이터 접근에는 [동기화]{.term}가 필요하다.
- 여러 실행 단위는 멀티코어 CPU에서 병렬로 실행될 수 있으며, 단일 코어에서도 스케줄링을 통해 번갈아 실행될 수 있다.
- [스레드 풀]{.term}은 스레드를 무제한 생성하지 않고 미리 정해진 수의 스레드를 재사용하는 방식이다.

## 핵심 포인트
- [멀티프로세스는 장애 격리와 보안 경계가 중요할 때 유리하다.]{.accent}
- 한 프로세스가 비정상 종료되어도 다른 프로세스가 살아 있을 수 있어 장애 영향 범위를 줄이기 쉽다.
- 프로세스마다 주소 공간이 분리되므로 메모리 사용량이 늘고, 통신에는 IPC 비용이 든다.
- [fork]{.term} 이후에는 [Copy-on-Write]{.term} 덕분에 처음부터 모든 메모리를 복사하지 않을 수 있다.
- [멀티스레드는 같은 데이터를 자주 공유하고 빠르게 협업해야 할 때 유리하다.]{.accent}
- 스레드는 같은 힙과 전역 데이터를 공유하므로 통신 비용은 낮지만 경쟁 상태, 데드락, 데이터 오염 위험이 커진다.
- 스레드를 너무 많이 만들면 컨텍스트 스위칭과 스케줄링 비용이 늘어 성능이 오히려 떨어질 수 있다.
- CPU 집약 작업은 코어 수에 맞춘 병렬성이 중요하고, I/O 집약 작업은 대기 시간 동안 다른 작업을 처리하는 구조가 중요하다.
- 웹 브라우저처럼 탭이나 렌더러를 프로세스로 분리하면 안정성과 보안이 좋아지고, 서버 워커처럼 공유 상태가 많은 작업은 스레드 모델이 효율적일 수 있다.
- [선택 기준은 속도 하나가 아니라 격리, 통신 빈도, 장애 영향 범위, 메모리 비용, 동기화 난이도다.]{.warning}

## 면접 질문
- 멀티프로세스와 멀티스레드를 비교해보세요.
- 웹 서버에서 두 방식 중 어떤 상황에 어떤 선택을 할 수 있나요?
- 멀티프로세스가 안정성에 유리한 이유는 무엇인가요?
- 멀티스레드에서 성능 이점과 위험이 동시에 생기는 이유는 무엇인가요?
- IPC 비용과 동기화 비용은 각각 어떤 상황에서 문제가 되나요?
- 스레드 풀을 사용하는 이유는 무엇인가요?
- CPU-bound 작업과 I/O-bound 작업에서 병렬 처리 전략이 어떻게 달라질 수 있나요?

## 확인 문제
- 멀티스레드는 항상 안전할까?
- 멀티프로세스는 자원 공유가 쉬운 구조일까?
- 멀티프로세스는 장애 영향 범위를 줄이는 데 도움이 될까?
- 멀티스레드는 같은 힙 데이터를 공유할 수 있을까?
- 스레드를 무한정 늘리면 항상 성능이 좋아질까?
- 프로세스 간 데이터 교환에는 IPC가 필요할까?
