> [프로세스는 운영체제가 자원을 보호하고 관리하는 단위이고, 스레드는 CPU가 실제로 실행하는 흐름 단위다.]{.lead}

## 정의
![[process-thread-memory.png]]

- [프로그램]{.term}은 디스크에 저장된 실행 파일이고, [프로세스]{.term}는 그 프로그램이 메모리에 올라와 실행 중인 상태다.
- 프로세스는 독립적인 [가상 주소 공간]{.term}, 코드 영역, 데이터 영역, 힙, 스택, 열린 파일, 권한 같은 자원 정보를 가진다.
- 운영체제는 [PCB]{.term}에 프로세스 ID, 상태, 레지스터 값, 스케줄링 정보, 메모리 정보를 저장해 프로세스를 관리한다.
- [스레드]{.term}는 프로세스 안에서 실행되는 흐름이며, 같은 프로세스의 코드, 데이터, 힙, 파일 같은 자원을 공유한다.
- 각 스레드는 독립적인 스택, 프로그램 카운터, 레지스터 문맥을 가진다.
- 운영체제는 스레드 실행 상태를 관리하기 위해 [TCB]{.term}와 같은 스레드 제어 정보를 사용한다.
- 서로 다른 프로세스는 기본적으로 메모리를 직접 공유하지 않기 때문에 데이터를 주고받으려면 [IPC]{.term}가 필요하다.

## 핵심 포인트
- [프로세스는 격리와 자원 소유의 단위, 스레드는 실행과 스케줄링의 단위에 가깝다.]{.accent}
- 프로세스는 서로 격리되어 안정성이 높지만, 생성과 전환 비용이 상대적으로 크다.
- 스레드는 같은 주소 공간을 공유하므로 통신이 빠르지만, 공유 데이터 접근 순서에 따라 [경쟁 상태]{.term}가 생길 수 있다.
- 스레드마다 스택이 분리되는 이유는 함수 호출, 지역 변수, 반환 주소 같은 실행 흐름이 서로 달라야 하기 때문이다.
- 힙과 전역 데이터는 같은 프로세스의 스레드끼리 공유되므로 [임계 구역]{.term}에는 동기화가 필요하다.
- 컨텍스트 스위칭은 프로세스와 스레드 모두에서 발생할 수 있지만, 프로세스 전환은 주소 공간 전환과 캐시/TLB 영향 때문에 더 무거울 수 있다.
- [한 스레드의 크래시는 같은 프로세스 전체에 영향을 줄 수 있다.]{.warning}
- CPU 집약 작업은 병렬 실행 단위를 늘릴 수 있고, I/O 작업은 대기 시간을 다른 스레드의 실행으로 숨길 수 있다.
- 프로세스와 스레드는 “어느 쪽이 더 좋다”가 아니라 격리, 통신 비용, 장애 영향 범위, 동기화 난이도로 선택한다.

## 면접 질문
- 프로세스와 스레드의 차이를 설명해보세요.
- 프로그램과 프로세스는 어떻게 다른가요?
- PCB와 TCB에는 어떤 정보가 들어가나요?
- 스레드는 왜 스택을 따로 가지나요?
- 같은 프로세스의 스레드가 공유하는 영역과 독립적으로 가지는 영역은 무엇인가요?
- 프로세스 전환이 스레드 전환보다 무거울 수 있는 이유는 무엇인가요?
- 멀티스레드에서 동기화가 필요한 이유는 무엇인가요?

## 확인 문제
- 서로 다른 프로세스는 기본적으로 메모리를 공유할까?
- 같은 프로세스의 스레드는 힙을 공유할까?
- 스레드는 각자 스택과 프로그램 카운터를 가질까?
- 공유 데이터를 여러 스레드가 동시에 바꾸면 경쟁 상태가 생길 수 있을까?
- 프로세스 간 통신에는 IPC가 필요할까?
