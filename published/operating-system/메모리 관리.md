> [메모리 관리는 제한된 물리 메모리를 여러 프로세스가 안전하고 효율적으로 쓰도록 주소 공간을 나누고 보호하는 운영체제의 핵심 기능이다.]{.lead}

## 정의
- [메모리 관리]{.term}는 프로세스에 메모리를 할당하고, 접근 권한을 보호하며, 논리 주소를 물리 주소로 연결하는 작업이다.
- 각 프로세스는 자신만의 [주소 공간]{.term}을 가진 것처럼 실행되고, 운영체제와 하드웨어는 실제 물리 메모리 위치를 숨긴다.
- 프로세스 주소 공간은 보통 [Code 영역]{.term}, [Data 영역]{.term}, [Heap 영역]{.term}, [Stack 영역]{.term}처럼 역할별 영역으로 나누어 이해한다.
- Code 영역은 실행할 명령어를 담고, Data 영역은 전역 변수와 정적 변수를 담는다.
- Heap 영역은 실행 중 동적으로 할당되는 메모리이고, Stack 영역은 함수 호출, 지역 변수, 반환 주소 같은 실행 문맥을 담는다.
- [MMU]{.term}는 CPU가 만든 가상 주소를 페이지 테이블 같은 정보를 사용해 물리 주소로 변환하는 하드웨어 장치다.
- [메모리 보호]{.term}는 한 프로세스가 다른 프로세스나 커널 영역을 함부로 읽고 쓰지 못하게 막는 기능이다.
- [단편화]{.term}는 메모리의 남는 공간이 효율적으로 쓰이지 못하는 문제다.
- [스와핑]{.term}은 메모리가 부족할 때 일부 데이터를 디스크로 내리거나 다시 올리는 방식이다.
- 페이징, 세그멘테이션, 가상 메모리는 모두 메모리를 더 안전하고 유연하게 관리하기 위해 발전한 기법이다.

## 핵심 포인트
- [메모리 관리는 효율, 보호, 추상화를 동시에 다룬다.]{.accent}
- 프로그램은 연속된 주소 공간을 쓰는 것처럼 보지만, 실제 물리 메모리에서는 여러 위치에 나뉘어 배치될 수 있다.
- 주소 공간의 영역 구분을 이해하면 스레드가 왜 Stack은 따로 가지고 Heap은 공유하는지 연결해서 볼 수 있다.
- Heap은 자유롭게 동적 할당할 수 있지만 해제 누락, 과도한 할당, 단편화 문제가 생길 수 있다.
- Stack은 함수 호출 흐름에 맞춰 빠르게 할당/해제되지만 크기가 제한되어 깊은 재귀나 큰 지역 데이터에서 문제가 생길 수 있다.
- 주소 변환 덕분에 프로세스는 물리 메모리 위치를 직접 알 필요 없이 실행될 수 있다.
- 보호 비트와 권한 검사는 읽기, 쓰기, 실행 가능 여부를 제한해 잘못된 접근을 막는다.
- [내부 단편화]{.term}는 할당받은 블록 안에서 남는 공간이고, [외부 단편화]{.term}는 빈 공간이 흩어져 큰 연속 공간을 만들지 못하는 문제다.
- 페이징은 고정 크기 단위로 나누어 외부 단편화를 줄이는 데 유리하다.
- 세그멘테이션은 코드, 데이터, 스택처럼 의미 단위로 나누지만 가변 크기라 외부 단편화가 생길 수 있다.
- 스와핑과 요구 페이징은 실제 메모리에 필요한 데이터만 올려 물리 메모리 한계를 완화한다.
- [메모리가 부족할 때 디스크 I/O가 늘면 성능이 급격히 떨어질 수 있다.]{.warning}
