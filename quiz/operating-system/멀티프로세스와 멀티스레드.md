#### 객관식 | [756]
멀티프로세스의 장점으로 가장 알맞은 것은?
1. 모든 프로세스가 같은 힙을 직접 공유한다
2. ✅ 한 프로세스의 장애가 다른 프로세스에 덜 전파될 수 있다
3. IPC가 전혀 필요 없다
4. 항상 멀티스레드보다 메모리를 적게 쓴다
> 멀티프로세스는 주소 공간이 분리되어 장애 격리와 보안 경계 측면에서 유리합니다.

#### 객관식 | [757]
멀티스레드의 장점으로 가장 알맞은 것은?
1. 프로세스 간 주소 공간 격리가 강해진다
2. ✅ 같은 프로세스의 메모리를 공유해 통신 비용을 줄일 수 있다
3. 동기화 문제가 사라진다
4. 스레드는 컨텍스트 스위칭 비용이 전혀 없다
> 같은 프로세스의 스레드는 힙과 전역 데이터를 공유할 수 있어 협업이 빠르지만 동기화가 필요합니다.

#### OX | [758]
멀티스레드는 공유 메모리를 사용하기 쉬운 대신 경쟁 상태나 데드락 위험이 생길 수 있다.
> O
> 여러 스레드가 같은 데이터를 동시에 읽고 쓰면 접근 순서에 따라 결과가 달라질 수 있어 동기화가 필요합니다.

#### OX | [759]
프로세스를 여러 개로 나누면 IPC 비용과 메모리 비용이 전혀 발생하지 않는다.
> X
> 프로세스는 주소 공간이 분리되어 안정성은 높지만, 데이터 교환에는 IPC가 필요하고 메모리 사용량도 늘 수 있습니다.

#### 빈칸 | [760]
프로세스 간 데이터를 주고받는 통신 방식을 ___라고 한다.
> IPC
> Inter-Process Communication의 줄임말로 파이프, 메시지 큐, 공유 메모리, 소켓 등이 대표적입니다.

#### 빈칸 | [761]
스레드를 무제한 만들지 않고 정해진 수의 스레드를 재사용하는 구조를 ___이라고 한다.
> 스레드 풀
> 스레드 풀은 생성과 제거 비용을 줄이고 동시에 실행되는 작업 수를 제어하기 위해 사용합니다.

#### 객관식 | [762]
스레드를 너무 많이 만들었을 때 생길 수 있는 문제로 가장 알맞은 것은?
1. 주소 공간 격리가 자동으로 강해진다
2. ✅ 컨텍스트 스위칭과 스케줄링 비용이 늘어 성능이 떨어질 수 있다
3. 모든 데이터 경쟁이 사라진다
4. IPC가 항상 더 빨라진다
> 실행 단위가 너무 많으면 CPU가 실제 작업보다 전환과 관리에 더 많은 시간을 쓸 수 있습니다.

#### 객관식 | [763]
멀티프로세스와 멀티스레드 선택 기준으로 가장 거리가 먼 것은?
1. 장애 영향 범위
2. 데이터 공유 빈도
3. 동기화 난이도
4. ✅ 파일 이름의 길이
> 선택 기준은 격리, 통신 비용, 메모리 비용, 장애 영향 범위, 공유 데이터 동기화 난이도 같은 실행 특성입니다.

#### 빈칸 | [776]
fork 이후 실제 쓰기가 발생하기 전까지 메모리 페이지 복사를 미루는 최적화는 ___이다.
> Copy-on-Write
> Copy-on-Write는 부모와 자식 프로세스가 같은 페이지를 공유하다가 쓰기가 발생할 때 복사해 메모리 비용을 줄입니다.

#### 객관식 | [777]
CPU-bound 작업을 병렬 처리할 때 고려할 점으로 가장 알맞은 것은?
1. CPU 사용량은 중요하지 않다
2. ✅ 코어 수와 실제 연산량을 고려해 실행 단위를 조절해야 한다
3. 스레드를 무한히 늘리면 항상 빨라진다
4. 디스크 대기 시간만 줄이면 된다
> CPU-bound 작업은 계산이 병목이므로 코어 수보다 실행 단위를 과하게 늘리면 전환 비용이 커질 수 있습니다.

#### 객관식 | [778]
I/O-bound 작업의 특징으로 가장 알맞은 것은?
1. 대부분의 시간이 CPU 계산에만 쓰인다
2. ✅ 네트워크나 디스크 응답을 기다리는 시간이 성능에 큰 영향을 준다
3. 공유 자원이 없어 동기화가 불필요하다
4. 프로세스 격리와 무관하게 항상 하나의 스레드만 필요하다
> I/O-bound 작업은 대기 시간이 많기 때문에 기다리는 동안 다른 작업을 처리할 수 있는 구조가 효율적입니다.

#### 빈칸 | [779]
여러 스레드가 공유 자원에 안전하게 접근하도록 실행 순서를 조절하는 작업은 ___이다.
> 동기화
> 동기화는 임계 구역을 보호해 경쟁 상태와 데이터 오염을 줄이는 역할을 합니다.
