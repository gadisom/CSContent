#### 빈칸 | [308]
메모리 단편화 중 할당된 블록 사이에 사용할 수 없는 작은 공간이 생기는 현상을 ___ 단편화라 한다.
> 외부
> 외부 단편화는 전체 여유 공간은 충분하나 연속되지 않아 할당이 불가한 현상입니다.

#### 객관식 | [764]
운영체제가 메모리를 관리하는 이유로 가장 거리가 먼 것은?
1. 프로세스마다 안전한 주소 공간을 제공하기 위해
2. 제한된 물리 메모리를 효율적으로 쓰기 위해
3. 잘못된 메모리 접근을 막기 위해
4. ✅ CPU 명령어 집합을 새로 정의하기 위해
> 메모리 관리는 할당, 보호, 주소 변환, 효율적인 물리 메모리 사용과 관련됩니다.

#### OX | [765]
프로세스는 자신만의 연속된 주소 공간을 가진 것처럼 실행될 수 있다.
> O
> 가상 주소 공간 덕분에 프로세스는 실제 물리 배치와 분리된 논리 주소를 사용할 수 있습니다.

#### 빈칸 | [766]
CPU가 만든 가상 주소를 물리 주소로 변환하는 하드웨어 장치는 ___이다.
> MMU
> MMU는 Memory Management Unit의 줄임말이며 페이지 테이블 등의 정보를 사용해 주소 변환을 수행합니다.

#### 객관식 | [767]
내부 단편화에 대한 설명으로 가장 알맞은 것은?
1. 빈 공간이 여러 곳에 흩어져 큰 연속 공간을 만들 수 없는 현상
2. ✅ 할당받은 블록 안에서 실제로 쓰지 못하고 남는 공간이 생기는 현상
3. 프로세스가 CPU를 기다리는 현상
4. 페이지 테이블이 캐시에 저장되는 현상
> 내부 단편화는 할당 단위가 실제 필요한 크기보다 커서 블록 내부에 낭비 공간이 생기는 문제입니다.

#### 객관식 | [768]
외부 단편화에 대한 설명으로 가장 알맞은 것은?
1. ✅ 총 여유 공간은 있어도 연속된 공간이 부족해 할당하지 못하는 현상
2. 할당된 블록 내부에 작은 낭비 공간이 생기는 현상
3. 주소 변환 결과가 TLB에 저장되는 현상
4. 스레드가 스택을 따로 가지는 현상
> 외부 단편화는 빈 공간이 흩어져 있어 큰 연속 메모리 요청을 만족시키기 어려운 문제입니다.

#### OX | [769]
메모리 보호는 한 프로세스가 다른 프로세스나 커널 영역을 함부로 접근하지 못하게 하는 데 필요하다.
> O
> 운영체제는 주소 공간과 권한 검사를 통해 잘못된 메모리 접근을 막고 시스템 안정성을 높입니다.

#### 빈칸 | [770]
메모리가 부족할 때 일부 데이터를 디스크로 내리거나 다시 올리는 방식을 ___이라고 한다.
> 스와핑
> 스와핑은 물리 메모리 부족을 완화할 수 있지만 디스크 I/O가 늘면 성능이 크게 떨어질 수 있습니다.

#### 객관식 | [771]
페이징이 외부 단편화를 줄이는 데 유리한 이유로 가장 알맞은 것은?
1. 모든 프로세스를 하나의 연속 공간에만 배치하기 때문이다
2. ✅ 고정 크기 페이지와 프레임 단위로 나누어 비연속 배치가 가능하기 때문이다
3. 디스크를 전혀 사용하지 않기 때문이다
4. 스레드 동기화를 자동으로 해결하기 때문이다
> 페이징은 물리 메모리를 고정 크기 프레임으로 나누고, 프로세스의 페이지를 여러 프레임에 나누어 배치할 수 있습니다.

#### 객관식 | [772]
프로세스 주소 공간의 Code 영역에 대한 설명으로 가장 알맞은 것은?
1. 함수 호출마다 생성되는 지역 변수를 저장한다
2. 동적으로 할당된 객체를 저장한다
3. ✅ 실행할 기계어 명령어를 저장한다
4. 페이지 교체 알고리즘을 결정한다
> Code 영역은 프로그램이 실행할 명령어를 담는 영역이며 보통 읽기/실행 권한 중심으로 관리됩니다.

#### 빈칸 | [773]
실행 중 동적으로 할당되는 메모리는 주로 ___ 영역에 저장된다.
> Heap
> Heap 영역은 런타임에 필요한 객체나 데이터가 동적으로 할당되는 공간입니다.

#### 빈칸 | [774]
함수 호출, 지역 변수, 반환 주소 같은 실행 문맥은 주로 ___ 영역에서 관리된다.
> Stack
> Stack 영역은 함수 호출 흐름에 따라 빠르게 할당되고 해제되는 실행 문맥을 저장합니다.

#### OX | [775]
같은 프로세스 안의 여러 스레드는 일반적으로 Heap을 공유하지만 Stack은 각자 따로 가진다.
> O
> 스레드는 같은 프로세스의 주소 공간을 공유하므로 Heap은 함께 접근할 수 있고, 함수 호출 흐름을 위해 Stack은 독립적으로 가집니다.
