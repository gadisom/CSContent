# 자료구조 단어장

## Array
- answer: 같은 종류의 데이터를 연속된 메모리 공간에 저장하는 자료구조
- detail: 배열은 인덱스로 빠르게 접근할 수 있지만, 중간 삽입과 삭제는 뒤 원소를 이동해야 해서 비용이 커질 수 있다.

## Linked List
- answer: 각 노드가 다음 노드의 위치를 가리키며 연결되는 자료구조
- detail: 연결 리스트는 중간 삽입과 삭제가 비교적 유연하다. 대신 특정 위치에 바로 접근하려면 앞에서부터 따라가야 한다.

## Stack
- answer: 나중에 넣은 데이터가 먼저 나오는 자료구조
- detail: Last In First Out 구조다. 함수 호출, 실행 취소, 괄호 검사처럼 최근 항목부터 처리해야 할 때 쓰인다.

## Queue
- answer: 먼저 넣은 데이터가 먼저 나오는 자료구조
- detail: First In First Out 구조다. 작업 대기열, BFS, 이벤트 처리처럼 들어온 순서대로 처리해야 할 때 쓰인다.

## Hash Table
- answer: 키를 해시 함수로 변환해 값을 빠르게 찾는 자료구조
- detail: 평균적으로 검색, 삽입, 삭제가 빠르다. 해시 충돌이 많아지면 성능이 떨어질 수 있어 충돌 처리 방식이 중요하다.

## Tree
- answer: 계층 관계를 부모와 자식 노드로 표현하는 자료구조
- detail: 트리는 하나의 루트에서 시작해 여러 자식으로 뻗어나간다. 파일 시스템, 조직도, 탐색 구조 등에 사용된다.

## Binary Search Tree
- answer: 왼쪽은 작은 값, 오른쪽은 큰 값을 두는 이진 트리
- detail: Binary Search Tree는 정렬된 구조를 유지해 탐색을 빠르게 하려는 트리다. 균형이 깨지면 연결 리스트처럼 느려질 수 있다.

## Heap
- answer: 부모와 자식 사이에 우선순위 규칙을 유지하는 완전 이진 트리
- detail: 최대 힙은 부모가 자식보다 크고, 최소 힙은 부모가 자식보다 작다. 최댓값이나 최솟값을 빠르게 꺼낼 때 사용한다.

## Priority Queue
- answer: 들어온 순서가 아니라 우선순위가 높은 항목을 먼저 꺼내는 자료구조
- detail: 우선순위 큐는 보통 힙으로 구현한다. 작업 스케줄링, 다익스트라 알고리즘 같은 곳에서 사용된다.

## Graph
- answer: 정점과 간선으로 여러 대상의 연결 관계를 표현하는 자료구조
- detail: 그래프는 방향, 가중치, 순환 여부에 따라 다양한 형태를 가진다. 네트워크, 경로 탐색, 관계 분석에 자주 쓰인다.

## Node
- answer: 자료구조 안에서 하나의 데이터를 담는 기본 단위
- detail: 노드는 연결 리스트, 트리, 그래프에서 데이터와 연결 정보를 함께 표현할 때 자주 사용된다.

## Edge
- answer: 그래프에서 두 노드를 연결하는 관계
- detail: 간선은 방향과 가중치를 가질 수 있다. 연결 관계 자체가 중요한 문제에서 핵심 요소가 된다.

## Index
- answer: 배열 같은 순차 자료구조에서 위치를 나타내는 번호
- detail: 인덱스를 사용하면 특정 위치의 원소에 바로 접근할 수 있다. 보통 0부터 시작하는 언어가 많다.

## Collision
- answer: 서로 다른 키가 같은 해시 위치로 매핑되는 상황
- detail: 해시 충돌은 피하기 어렵기 때문에 체이닝이나 오픈 어드레싱 같은 방식으로 처리한다.
