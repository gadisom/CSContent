# 운영체제 단어장

## Process
- answer: 실행 중인 프로그램의 독립적인 실행 단위
- detail: 프로세스는 자신만의 메모리 공간과 자원 정보를 가진다. 운영체제는 프로세스를 생성, 스케줄링, 종료하며 관리한다.

## Thread
- answer: 프로세스 안에서 실행 흐름을 담당하는 더 작은 실행 단위
- detail: 스레드는 같은 프로세스의 메모리 공간을 공유한다. 공유 자원에 동시에 접근할 수 있어 동기화가 중요하다.

## Context Switching
- answer: CPU가 실행 중인 작업을 바꾸기 위해 상태를 저장하고 복원하는 과정
- detail: 컨텍스트 스위칭은 멀티태스킹을 가능하게 하지만, 상태 저장과 복원 비용이 발생한다.

## PCB
- answer: 운영체제가 프로세스 상태를 관리하기 위해 사용하는 정보 묶음
- detail: Process Control Block의 줄임말이다. 프로세스 ID, 레지스터 값, 스케줄링 정보, 메모리 정보 등을 담는다.

## Scheduler
- answer: 어떤 프로세스나 스레드에 CPU를 줄지 결정하는 운영체제 구성 요소
- detail: 스케줄러는 공정성, 응답 시간, 처리량 같은 기준에 따라 실행 순서를 정한다.

## Round Robin
- answer: 각 작업에 정해진 시간만큼 CPU를 번갈아 주는 스케줄링 방식
- detail: 시간 할당량이 너무 작으면 컨텍스트 스위칭이 늘고, 너무 크면 응답성이 떨어질 수 있다.

## Deadlock
- answer: 여러 작업이 서로의 자원을 기다리며 더 이상 진행하지 못하는 상태
- detail: 교착 상태라고도 부른다. 상호 배제, 점유와 대기, 비선점, 순환 대기 조건이 함께 만족될 때 발생할 수 있다.

## Mutex
- answer: 공유 자원에 한 번에 하나의 실행 흐름만 접근하도록 막는 동기화 도구
- detail: Mutual Exclusion의 줄임말이다. 임계 구역을 보호하지만 잘못 사용하면 데드락이나 성능 저하를 만들 수 있다.

## Semaphore
- answer: 정해진 개수만큼의 접근 허용 수를 관리하는 동기화 도구
- detail: 세마포어는 카운터를 기반으로 여러 실행 흐름의 진입을 제어한다. 이진 세마포어는 뮤텍스와 비슷하게 쓰일 수 있다.

## Monitor
- answer: 공유 데이터와 동기화 로직을 함께 묶어 안전하게 접근하게 하는 구조
- detail: 모니터는 락과 조건 변수를 추상화해 동기화 코드를 더 안전하게 구성하도록 돕는다.

## Virtual Memory
- answer: 실제 메모리보다 큰 논리적 메모리 공간을 제공하는 기법
- detail: 가상 메모리는 프로세스마다 독립적인 주소 공간을 제공한다. 필요한 부분만 실제 메모리에 올려 메모리를 효율적으로 사용한다.

## Page Fault
- answer: 필요한 페이지가 메모리에 없어 디스크에서 가져와야 하는 상황
- detail: 페이지 폴트가 발생하면 운영체제가 필요한 페이지를 적재한다. 너무 자주 발생하면 성능이 크게 떨어질 수 있다.

## TLB
- answer: 가상 주소와 물리 주소 변환 결과를 빠르게 찾기 위한 캐시
- detail: Translation Lookaside Buffer의 줄임말이다. 페이지 테이블 접근 비용을 줄여 주소 변환 속도를 높인다.

## Cache Locality
- answer: 가까운 시간이나 가까운 주소의 데이터를 다시 사용할 가능성이 높은 성질
- detail: 지역성은 시간 지역성과 공간 지역성으로 나눌 수 있다. 캐시 메모리는 이 성질을 이용해 성능을 높인다.

## IPC
- answer: 서로 다른 프로세스가 데이터를 주고받는 통신 방식
- detail: Inter-Process Communication의 줄임말이다. 파이프, 메시지 큐, 공유 메모리, 소켓 등이 대표적인 IPC 방식이다.
