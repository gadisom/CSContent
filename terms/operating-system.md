# 운영체제 단어장

## Process
- answer: 실행 중인 프로그램의 독립적인 실행 단위
- detail: 프로세스는 자신만의 메모리 공간과 자원 정보를 가진다. 운영체제는 프로세스를 생성, 스케줄링, 종료하며 관리한다.

## Thread
- answer: 프로세스 안에서 실행 흐름을 담당하는 더 작은 실행 단위
- detail: 스레드는 같은 프로세스의 메모리 공간을 공유한다. 공유 자원에 동시에 접근할 수 있어 동기화가 중요하다.

## Program
- answer: 디스크에 저장된 실행 가능한 코드와 데이터
- detail: 프로그램은 아직 실행 중인 상태가 아니다. 운영체제가 프로그램을 메모리에 올리고 자원을 할당하면 프로세스가 된다.

## Address Space
- answer: 프로세스가 사용할 수 있도록 제공되는 논리적인 메모리 범위
- detail: 각 프로세스는 독립적인 가상 주소 공간을 가진다. 이 격리 덕분에 다른 프로세스의 메모리를 직접 침범하기 어렵다.

## TCB
- answer: 운영체제가 스레드 상태를 관리하기 위해 사용하는 정보 묶음
- detail: Thread Control Block의 줄임말이다. 스레드 ID, 레지스터 문맥, 스택 포인터, 상태 정보 등을 관리하는 데 사용된다.

## Race Condition
- answer: 여러 실행 흐름의 접근 순서에 따라 결과가 달라지는 상황
- detail: 경쟁 상태는 공유 데이터를 동시에 읽고 쓰는 멀티스레드 환경에서 자주 발생한다. 임계 구역을 동기화해 예방한다.

## Critical Section
- answer: 동시에 접근하면 문제가 생길 수 있어 보호가 필요한 코드 영역
- detail: 임계 구역은 공유 자원을 읽거나 수정하는 구간이다. 뮤텍스, 세마포어, 모니터 같은 동기화 도구로 보호한다.

## Multi-process
- answer: 여러 프로세스를 사용해 작업을 나누어 실행하는 방식
- detail: 각 프로세스는 독립 주소 공간을 가져 장애 격리와 보안에 유리하다. 대신 IPC 비용과 메모리 비용이 커질 수 있다.

## Multi-thread
- answer: 하나의 프로세스 안에서 여러 스레드가 함께 실행되는 방식
- detail: 스레드들은 같은 주소 공간을 공유해 통신이 빠르다. 공유 데이터 접근에는 동기화가 필요하다.

## Thread Pool
- answer: 정해진 수의 스레드를 미리 두고 작업마다 재사용하는 구조
- detail: 스레드 생성과 제거 비용을 줄이고 동시에 실행되는 작업 수를 제한한다. 서버나 비동기 작업 처리에서 자주 쓰인다.

## Fault Isolation
- answer: 한 부분의 장애가 다른 부분으로 전파되지 않도록 경계를 두는 성질
- detail: 멀티프로세스 구조는 주소 공간과 실행 단위가 분리되어 장애 영향 범위를 줄이는 데 유리하다.

## Copy-on-Write
- answer: 실제 변경이 일어나기 전까지 복사를 미루는 최적화
- detail: 프로세스 fork 이후 같은 메모리 페이지를 공유하다가 쓰기가 발생할 때 복사해 메모리 비용을 줄일 수 있다.

## Fork
- answer: 실행 중인 프로세스를 바탕으로 새 프로세스를 만드는 동작
- detail: fork 이후 부모와 자식 프로세스는 독립적으로 실행된다. Copy-on-Write와 함께 쓰이면 실제 변경 전까지 메모리 복사를 늦출 수 있다.

## Shared Memory
- answer: 여러 실행 흐름이 같은 메모리 영역을 함께 사용하는 방식
- detail: 스레드는 같은 프로세스의 메모리를 자연스럽게 공유하고, 프로세스끼리는 IPC 방식으로 공유 메모리를 사용할 수 있다. 빠르지만 동기화가 필요하다.

## Synchronization
- answer: 공유 자원 접근 순서를 맞춰 데이터 충돌을 막는 작업
- detail: 동기화는 경쟁 상태를 줄이기 위해 임계 구역에 한 번에 정해진 실행 흐름만 들어가도록 조절한다. 뮤텍스, 세마포어, 모니터가 대표적이다.

## CPU-bound
- answer: 실행 시간의 대부분을 CPU 계산에 쓰는 작업
- detail: CPU-bound 작업은 코어 수와 연산량이 성능에 큰 영향을 준다. 실행 단위를 과도하게 늘리면 컨텍스트 스위칭 비용이 커질 수 있다.

## I/O-bound
- answer: 실행 시간의 상당 부분을 입출력 대기에 쓰는 작업
- detail: I/O-bound 작업은 네트워크, 디스크, DB 응답을 기다리는 시간이 많다. 대기 중 다른 작업을 처리하도록 구성하면 효율이 좋아진다.

## Memory Management
- answer: 제한된 메모리를 프로세스에 안전하고 효율적으로 배분하는 운영체제 기능
- detail: 메모리 관리는 할당, 보호, 주소 변환, 단편화 완화, 스와핑 같은 문제를 함께 다룬다.

## MMU
- answer: 가상 주소를 물리 주소로 변환하는 하드웨어 장치
- detail: Memory Management Unit의 줄임말이다. 페이지 테이블과 TLB를 활용해 주소 변환과 보호 검사를 수행한다.

## Logical Address
- answer: 프로세스가 사용하는 가상의 주소
- detail: 논리 주소 또는 가상 주소라고 부른다. 실제 물리 메모리 위치와 분리되어 있어 주소 변환이 필요하다.

## Physical Address
- answer: 실제 메모리 하드웨어에서 접근되는 주소
- detail: 물리 주소는 RAM의 실제 위치를 가리킨다. 운영체제와 MMU가 논리 주소를 물리 주소로 변환한다.

## Internal Fragmentation
- answer: 할당받은 블록 내부에 사용하지 못하는 공간이 남는 현상
- detail: 고정 크기 블록을 사용할 때 요청 크기보다 큰 공간을 배정하면 내부 단편화가 생길 수 있다.

## External Fragmentation
- answer: 빈 공간이 흩어져 큰 연속 공간을 만들기 어려운 현상
- detail: 전체 여유 공간은 충분해도 연속된 공간이 부족하면 큰 메모리 요청을 만족시키지 못할 수 있다.

## Swapping
- answer: 메모리의 일부 내용을 디스크로 내리거나 다시 올리는 방식
- detail: 스와핑은 물리 메모리 부족을 완화하지만 디스크 I/O가 많아지면 성능이 크게 떨어질 수 있다.

## Code Segment
- answer: 프로그램이 실행할 명령어가 저장되는 메모리 영역
- detail: 코드 영역이라고도 부른다. 보통 읽기와 실행 권한 중심으로 관리되며, 실행 중 임의로 수정되지 않도록 보호된다.

## Data Segment
- answer: 전역 변수와 정적 변수가 저장되는 메모리 영역
- detail: 초기화된 데이터와 초기화되지 않은 데이터 영역으로 나누어 설명하기도 한다. 프로세스 실행 동안 유지되는 데이터가 포함된다.

## Heap
- answer: 실행 중 동적으로 할당되는 메모리 영역
- detail: 객체나 큰 데이터처럼 런타임에 크기와 생명주기가 결정되는 메모리를 저장한다. 해제 누락이나 단편화 문제가 생길 수 있다.

## Stack
- answer: 함수 호출과 지역 변수, 반환 주소를 관리하는 메모리 영역
- detail: 스택은 호출 흐름에 맞춰 빠르게 증가하고 줄어든다. 각 스레드는 보통 자신만의 스택을 가진다.

## Context Switching
- answer: CPU가 실행 중인 작업을 바꾸기 위해 상태를 저장하고 복원하는 과정
- detail: 컨텍스트 스위칭은 멀티태스킹을 가능하게 하지만, 상태 저장과 복원 비용이 발생한다.

## PCB
- answer: 운영체제가 프로세스 상태를 관리하기 위해 사용하는 정보 묶음
- detail: Process Control Block의 줄임말이다. 프로세스 ID, 레지스터 값, 스케줄링 정보, 메모리 정보 등을 담는다.

## Scheduler
- answer: 어떤 프로세스나 스레드에 CPU를 줄지 결정하는 운영체제 구성 요소
- detail: 스케줄러는 공정성, 응답 시간, 처리량 같은 기준에 따라 실행 순서를 정한다.

## Round Robin
- answer: 각 작업에 정해진 시간만큼 CPU를 번갈아 주는 스케줄링 방식
- detail: 시간 할당량이 너무 작으면 컨텍스트 스위칭이 늘고, 너무 크면 응답성이 떨어질 수 있다.

## Deadlock
- answer: 여러 작업이 서로의 자원을 기다리며 더 이상 진행하지 못하는 상태
- detail: 교착 상태라고도 부른다. 상호 배제, 점유와 대기, 비선점, 순환 대기 조건이 함께 만족될 때 발생할 수 있다.

## Mutex
- answer: 공유 자원에 한 번에 하나의 실행 흐름만 접근하도록 막는 동기화 도구
- detail: Mutual Exclusion의 줄임말이다. 임계 구역을 보호하지만 잘못 사용하면 데드락이나 성능 저하를 만들 수 있다.

## Semaphore
- answer: 정해진 개수만큼의 접근 허용 수를 관리하는 동기화 도구
- detail: 세마포어는 카운터를 기반으로 여러 실행 흐름의 진입을 제어한다. 이진 세마포어는 뮤텍스와 비슷하게 쓰일 수 있다.

## Monitor
- answer: 공유 데이터와 동기화 로직을 함께 묶어 안전하게 접근하게 하는 구조
- detail: 모니터는 락과 조건 변수를 추상화해 동기화 코드를 더 안전하게 구성하도록 돕는다.

## Virtual Memory
- answer: 실제 메모리보다 큰 논리적 메모리 공간을 제공하는 기법
- detail: 가상 메모리는 프로세스마다 독립적인 주소 공간을 제공한다. 필요한 부분만 실제 메모리에 올려 메모리를 효율적으로 사용한다.

## Page Fault
- answer: 필요한 페이지가 메모리에 없어 디스크에서 가져와야 하는 상황
- detail: 페이지 폴트가 발생하면 운영체제가 필요한 페이지를 적재한다. 너무 자주 발생하면 성능이 크게 떨어질 수 있다.

## TLB
- answer: 가상 주소와 물리 주소 변환 결과를 빠르게 찾기 위한 캐시
- detail: Translation Lookaside Buffer의 줄임말이다. 페이지 테이블 접근 비용을 줄여 주소 변환 속도를 높인다.

## Cache Locality
- answer: 가까운 시간이나 가까운 주소의 데이터를 다시 사용할 가능성이 높은 성질
- detail: 지역성은 시간 지역성과 공간 지역성으로 나눌 수 있다. 캐시 메모리는 이 성질을 이용해 성능을 높인다.

## IPC
- answer: 서로 다른 프로세스가 데이터를 주고받는 통신 방식
- detail: Inter-Process Communication의 줄임말이다. 파이프, 메시지 큐, 공유 메모리, 소켓 등이 대표적인 IPC 방식이다.
