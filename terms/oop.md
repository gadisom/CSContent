# 객체지향 단어장

## Object
- answer: 상태와 행동을 함께 가진 프로그램의 기본 단위
- detail: 객체는 속성과 메서드를 통해 현실의 대상이나 개념을 코드로 표현한다. 객체지향에서는 객체들이 서로 메시지를 주고받으며 동작한다.

## Class
- answer: 객체를 만들기 위한 설계도
- detail: 클래스는 객체가 가질 속성과 행동을 정의한다. 같은 클래스로 여러 인스턴스를 만들 수 있다.

## Instance
- answer: 클래스를 바탕으로 실제 메모리에 만들어진 객체
- detail: 인스턴스는 클래스의 정의를 실제 값과 함께 가진 실행 중 객체다. 같은 클래스의 인스턴스라도 상태는 서로 다를 수 있다.

## Encapsulation
- answer: 데이터와 동작을 하나로 묶고 외부 접근을 제한하는 원칙
- detail: 캡슐화는 객체 내부 구현을 숨기고 필요한 인터페이스만 드러낸다. 변경 범위를 줄이고 객체의 책임을 분명하게 만든다.

## Inheritance
- answer: 기존 타입의 속성과 동작을 새로운 타입이 물려받는 관계
- detail: 상속은 공통 기능을 재사용할 수 있게 해준다. 하지만 계층이 깊어지면 결합도가 높아질 수 있어 조심해서 사용한다.

## Abstraction
- answer: 중요한 특징만 드러내고 불필요한 세부 구현은 감추는 것
- detail: 추상화는 복잡한 대상을 필요한 관점으로 단순화한다. 인터페이스나 추상 클래스를 통해 역할 중심으로 설계할 수 있다.

## Polymorphism
- answer: 같은 호출이 실제 객체에 따라 다르게 동작하는 성질
- detail: 다형성은 공통 타입으로 여러 구현체를 다룰 수 있게 한다. 코드가 구체 클래스보다 역할에 의존하도록 돕는다.

## Interface
- answer: 구현보다 역할과 약속을 정의하는 타입
- detail: 인터페이스는 어떤 메서드를 제공해야 하는지 표현한다. 여러 구현체가 같은 인터페이스를 따를 수 있어 교체 가능성이 높아진다.

## Abstract Class
- answer: 일부 구현과 추상 메서드를 함께 가질 수 있는 기반 클래스
- detail: 추상 클래스는 직접 인스턴스화하기보다 하위 클래스의 공통 기반으로 사용된다.

## Overriding
- answer: 상위 타입의 메서드를 하위 타입에서 다시 구현하는 것
- detail: 오버라이딩은 다형성을 가능하게 하는 핵심 동작이다. 같은 메서드 호출이 실제 객체 타입에 따라 다르게 실행된다.

## Overloading
- answer: 같은 이름의 메서드를 매개변수 형태가 다르게 여러 개 정의하는 것
- detail: 오버로딩은 호출 시 전달한 인자의 개수나 타입에 따라 사용할 메서드가 결정된다.

## Dynamic Binding
- answer: 실행 시점의 실제 객체 타입에 따라 호출할 메서드가 결정되는 방식
- detail: 동적 바인딩은 다형성과 오버라이딩을 가능하게 한다. 컴파일 시점 타입보다 실제 인스턴스의 구현이 중요해진다.

## Dependency Injection
- answer: 객체가 필요한 의존성을 직접 만들지 않고 외부에서 전달받는 방식
- detail: 의존성 주입은 테스트와 교체를 쉽게 만든다. 객체가 구체 구현보다 인터페이스에 의존하도록 설계할 때 자주 사용된다.
