# 알고리즘 단어장

## Time Complexity
- answer: 입력 크기에 따라 실행 시간이 얼마나 증가하는지 나타내는 기준
- detail: 시간복잡도는 알고리즘의 성능을 입력 크기 n에 대한 증가 추세로 표현한다. 보통 Big O 표기법으로 최악 또는 상한 관점의 증가율을 설명한다.

## Space Complexity
- answer: 입력 크기에 따라 필요한 메모리가 얼마나 증가하는지 나타내는 기준
- detail: 공간복잡도는 알고리즘이 사용하는 추가 메모리의 양을 표현한다. 재귀 호출 스택, 보조 배열, 해시 테이블 같은 임시 저장 공간도 포함된다.

## Big O
- answer: 알고리즘의 증가율을 상한 중심으로 표현하는 표기법
- detail: Big O는 입력이 커질 때 실행 시간이나 메모리 사용량이 어느 정도 규모로 증가하는지 단순화해서 보여준다.

## Binary Search
- answer: 정렬된 범위에서 중간값을 기준으로 탐색 범위를 절반씩 줄이는 탐색
- detail: 이진 탐색은 정렬되어 있다는 조건이 필요하다. 매 단계마다 왼쪽 또는 오른쪽 절반을 버리기 때문에 시간복잡도는 보통 O(log n)이다.

## Sorting
- answer: 데이터를 정해진 기준에 따라 순서대로 재배치하는 작업
- detail: 정렬은 탐색, 중복 제거, 구간 처리 같은 많은 알고리즘의 전처리로 쓰인다. 선택하는 정렬 방식에 따라 시간복잡도와 안정성이 달라진다.

## Stable Sort
- answer: 값이 같은 원소들의 기존 상대 순서를 유지하는 정렬
- detail: 안정 정렬은 같은 점수의 학생을 이름순으로 이미 정렬해둔 뒤 점수순 정렬을 할 때처럼 이전 순서가 의미 있을 때 중요하다.

## Recursion
- answer: 함수가 자기 자신을 호출해서 문제를 더 작은 단위로 푸는 방식
- detail: 재귀는 종료 조건과 점화 관계가 핵심이다. 종료 조건이 없거나 잘못되면 호출이 끝나지 않거나 스택이 과도하게 쌓인다.

## Backtracking
- answer: 가능한 선택을 시도하다가 조건에 맞지 않으면 되돌아가는 탐색 방식
- detail: 백트래킹은 모든 경우를 무작정 끝까지 보지 않고, 불가능한 경로를 중간에 가지치기한다.

## Dynamic Programming
- answer: 겹치는 부분 문제의 결과를 저장해 중복 계산을 줄이는 기법
- detail: Dynamic Programming은 점화식과 저장 테이블을 기반으로 한다. 같은 계산이 반복되는 최적화 문제에서 자주 사용된다.

## Greedy
- answer: 매 순간 가장 좋아 보이는 선택을 반복하는 알고리즘 전략
- detail: 그리디는 지역 최적 선택이 전체 최적해로 이어진다는 조건이 맞아야 한다. 조건이 맞지 않으면 빠르지만 틀린 답을 만들 수 있다.

## BFS
- answer: 가까운 정점부터 차례대로 방문하는 그래프 탐색
- detail: Breadth-First Search의 줄임말이다. 큐를 사용하며, 가중치가 없는 그래프에서 최단 거리 탐색에 자주 쓰인다.

## DFS
- answer: 한 경로를 깊게 따라간 뒤 되돌아오며 방문하는 그래프 탐색
- detail: Depth-First Search의 줄임말이다. 재귀 또는 스택으로 구현하며, 경로 탐색이나 연결 요소 확인에 자주 쓰인다.

## Vertex
- answer: 그래프에서 하나의 대상이나 지점을 나타내는 정점
- detail: 정점은 노드라고도 부른다. 사람, 도시, 페이지처럼 관계의 대상이 되는 요소를 표현한다.

## Edge
- answer: 그래프에서 두 정점 사이의 관계나 연결
- detail: 간선은 방향이 있을 수도 있고 없을 수도 있다. 비용이나 거리 같은 가중치를 함께 가질 수도 있다.

## Brute Force
- answer: 가능한 경우를 모두 직접 확인하는 방식
- detail: 완전탐색이라고도 부른다. 구현은 단순하지만 경우의 수가 커지면 시간복잡도가 급격히 커질 수 있다.
